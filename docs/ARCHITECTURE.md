# Архітектура Mixer

Mixer — застосунок у смузі меню macOS 26+. Swift, AppKit, публічні Core Audio taps і невеликий C-обробник. Немає сторонніх runtime-залежностей, HAL-драйвера або фонового helper-застосунку.

## Компоненти

- `Mixer`: NSStatusItem, панель без активації застосунку, нативні елементи керування й меню.
- `MixerCore`: моделі, збереження налаштувань, визначення аудіопроцесів і виходів, керування маршрутами та автозапуск.
- `AudioRealtime`: C-обробник Float32 і читання ресурсних метрик через системні API.

Керування Core Audio виконується на послідовній control queue. Стан змінюється через системні повідомлення; постійного polling немає. UI отримує snapshots. Коли панель закрита, рядки, іконки й layout для неї не оновлюються; кеш малих іконок обмежений.

## Аудіошлях

1. При 100%, без mute і з системним виходом маршрут Mixer не створюється.
2. Змінені налаштування активної програми створюють приватний `CATapDescription` для її аудіопроцесів із `mutedWhenTapped`.
3. Приватний aggregate device поєднує tap і фізичний вихід. Вихід задає час; для tap увімкнено drift compensation.
4. IOProc читає звук tap, застосовує gain і заповнює вихідний буфер. Фізичні input streams вимикаються для цього IOProc.
5. При завершенні відтворення або демонтажі маршруту прибираються IOProc, aggregate, tap і render context.

У realtime callback немає allocation, блокувань або викликів Swift. Gain передається атомарно; короткий ramp згладжує зміни. Шкала повзунка відділена від амплітуди: `gain = volume²`; 50% відповідає амплітуді 0,25, приблизно −12 дБ.

Формати перевіряються до запуску. Невдалий маршрут не перезапускається нескінченно з тією самою конфігурацією; повтор можливий після зміни стану або явного повторного підключення. При завершенні Mixer демонтує маршрути, повертаючи звичайне відтворення джерел.

## Налаштування й дозволи

Налаштування програм зберігаються за bundle ID, виходи — за UID. Невідомі PID-only процеси не зберігаються між запусками. Helper-процеси зіставляються з зовнішніми app bundles та батьківськими процесами; це не гарантує окремих рядків для вкладок браузера.

Після від’єднання виходу тимчасово використовується системний пристрій; UID зберігається для повторного підключення. Зміни sample rate або набору процесів перебудовують відповідний маршрут.

Перший запуск ініціює стандартний запит macOS на системний звук через короткий input-only aggregate із глобальним приватним unmuted tap. Ресурси прибираються після спроби. Прапорець onboarding означає лише, що спробу запиту виконано; він не є підтвердженням дозволу. Доступ до екрана або мікрофона не запитується. Аудіо не записується у файли й не передається мережею.

## Нативна панель

NSPanel використовує nonactivating-поведінку й системний матеріал popover. Повторне натискання іконки закриває панель; Escape спочатку закриває відкритий список виходів. Фокус і прокручування керуються без глобального keyboard monitor.

Геометрія обирає екран за іконкою, враховує visibleFrame, від’ємні координати та висоту viewport. Зміна конфігурації екранів або Space закриває панель. Слухачі геометрії існують лише під час її показу.

Автозапуск використовує `SMAppService.mainApp`. Стан читається із системи при відкритті меню; реєстрація виконується тільки за дією користувача. Власного LaunchAgent немає.

## Перевірки

Core runner перевіряє моделі, збереження, PCM-обробку, шкалу gain, fake-сервіс автозапуску та геометрію. AppKit fixture використовує справжні views у прихованих вікнах для клавіатури, фокусу й прокручування; він не змінює звук або автозапуск користувача. Окремі скрипти перевіряють атомарну заміну bundle, підпис і ZIP.

Перший реліз перевірено на Mac розробника. Незалежна перевірка завантаження й оновлення на іншому Mac ще очікується. Для першого релізу підтримується Apple Silicon; старіші macOS та Intel не перевірені.
