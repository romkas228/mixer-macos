# Підписування Mixer

Mixer можна зібрати для себе або підписувати постійною identity для оновлень. Приватний ключ автора не потрібен для локальної збірки й не публікується.

## Власна локальна збірка

У свіжій копії репозиторію без `.mixer-signing/` команда `./scripts/build.sh` використовує **ad-hoc** підпис. Після зміни коду macOS може знову запросити доступ до системного звуку.

## Постійний власний сертифікат

1. У Ключарі відкрий **Асистент сертифікатів → Створити сертифікат**.
2. Обери власну назву, **Self Signed Root** і **Code Signing**. Збережи сертифікат із приватним ключем у login keychain.
3. Переглянь доступні identity й налаштуй точний SHA-1 fingerprint свого сертифіката:

```sh
./scripts/signing.sh list
./scripts/signing.sh configure YOUR_40_CHARACTER_SHA1_FINGERPRINT
./scripts/build.sh
./scripts/signing.sh verify
```

Скрипт приймає лише 40-символьний шістнадцятковий відбиток і перевіряє наявність відповідного ключа. Локальна конфігурація та baseline designated requirement зберігаються у `.mixer-signing/`, яка ігнорується Git. Приватний ключ залишається в Ключарі. Після налаштування повторний `configure` для кожного оновлення не потрібен.

Якщо налаштована identity недоступна, збірка зупиняється. Автоматичного повернення до ad-hoc немає. `prepare SHA1` може зафіксувати вибір до доступності ключа та заблокувати ad-hoc до успішного `configure`.

Designated requirement зберігає bundle ID `local.mixer.Mixer` і перевіряє підписувача. Він не повинен прив’язуватися до CDHash конкретної збірки або перевіряти лише bundle ID. Пакувальник додатково очікує правило, прив’язане до leaf certificate.

Власний сертифікат допомагає зберігати ідентичність між збірками. Він не надає Apple Developer ID чи нотаризацію; перший запуск завантаженої програми може вимагати ручного підтвердження macOS. Порядок: [Apple — Safely open apps](https://support.apple.com/en-us/102445).

## Збереження identity

Збережи сертифікат **разом із приватним ключем** у зашифрованому `.p12` через Ключар. Зберігай копію та пароль приватно, окремо від Mac і публічного репозиторію. Пароль задається у системному вікні; самого публічного сертифіката для відновлення identity недостатньо.

## Перевірки й пакування

```sh
./scripts/test-signing.sh
./scripts/test-release.sh
./scripts/release.sh
```

`test-signing.sh` потребує доступу до ключа, оскільки підписує дві змінені тимчасові збірки. Тести перевіряють сталість DR, відмову для підміненого ресурсу й іншого підписувача. Аудіодозвіл потрібно перевіряти окремим реальним оновленням.

`release.sh prepare` створює ZIP-кандидат з уже зібраного Mixer.app, LICENSE і NOTICE. `release.sh verify CANDIDATE` виконує нативну strict verification розпакованого застосунку та публікує готові локальні assets у `build/releases/`. Перевірка підпису вже зібраного пакета не потребує приватного ключа. Існуючі релізи не перезаписуються.

Збірка створюється у staging-папці; лише після підписування й перевірки весь bundle замінюється атомарно. LICENSE і NOTICE додаються до Resources перед підписуванням. Самопідписані релізи не нотаризуються цими скриптами.

Деталі ідентичності підпису: [Apple TN3127 — Inside Code Signing: Requirements](https://developer.apple.com/documentation/technotes/tn3127-inside-code-signing-requirements).
